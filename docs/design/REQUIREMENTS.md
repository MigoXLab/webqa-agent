# 测试用例管理平台 - 需求设计文档

## 1. 项目背景

本项目旨在构建一个业务测试用例管理和执行平台，支持：

- 业务环境(URL)和测试用例(Case)的增删改查
- 每个业务的 Case 通过 YAML 解析上传，也支持手动编写
- 每个业务的文件库管理（用于上传功能时选择文件）
- 用户执行
  - 可以通过选择业务环境和 Case 触发执行，返回测试报告 URL
  - 定时触发执行
- 执行结果记录管理（手动 + 定时）

## 2. 业务模型

```
业务
├── Case 池（30个统一管理）
│   ├── case1 [需登录] ✓
│   ├── case2 [需登录] ✓
│   ├── case3 [免登录] ✓
│   └── ...
│
├── 环境（URL + 登录配置 + ignore_rules）
│   ├── 生产 (https://chat.intern-ai.org.cn) + SSO登录 + 忽略规则
│   └── 测试 (https://staging.chat.intern-ai.org.cn) + SSO登录 + 忽略规则
│
├── 文件库（用于 Case step 选择）
│   ├── test.jpg
│   └── sample.pdf
│
└── 定时任务（单环境配置，读取最新 Case）
    ├── "每日生产环境测试" → [环境:生产 + 20个case（其中10个登录，10个免登录）]
    └── "每周测试环境回归" → [环境:测试 + 25个case（其中15个登录，10个免登录）]
```

```
执行结果展示
展示所有触发的执行结果：
报告 OSS URL、执行状态、执行时间、结果概览
```

```
用户可以选择已有的用例、选择执行环境、选择并发数、选择模型、并且编写cron表达式开启定时任务；每个业务可以创建多个定时任务：

1. 一个定时任务只能配置一个环境 + 多个用例 (简化版)
2. 定时任务执行时读取最新的 Case 内容
3. 定时触发和手动触发可以一起执行，且一个业务下上一次定时触发的任务还在执行也可以一起执行，但是目前所有业务有最大job上限次数
4. 如果超过5个任务，就排队等待空闲槽位
5. 定时任务执行失败不需要重试
6. 定时任务的执行历史记录不需要单独展示，但是需要一个标签记录这一条是手动触发还是定时触发
7. 前端需要 Cron 表达式的可视化编辑器，前后端都需要验证cron表达式，显示下一次执行时间预览显示的事东八区时间
```

## 3. 功能范围（MVP）

### 3.1 优先级划分

| 优先级 | 功能          | 说明                                                        |
| ------ | ------------- | ----------------------------------------------------------- |
| **P0** | 业务管理      | 业务的增删改查                                              |
| **P0** | 环境管理      | 环境（URL + 登录配置 + ignore_rules）的增删改查             |
| **P0** | Case 管理     | Case 的增删改查、YAML 导入/导出                             |
| **P0** | 手动执行      | 选择环境 + Cases 触发执行                                   |
| **P0** | 执行记录      | 查看执行历史和报告（OSS）**【全局】**                       |
| **P1** | 用例编辑+调试 | 全屏编辑页（YAML + Debug），路由 `/business/:bid/case/:cid` |
| **P1** | 定时任务      | Cron 表达式定时执行，支持多环境配置 **【全局】**            |
| **P1** | 文件管理      | 业务文件库上传，Case step 可选择                            |

### 3.2 功能详述

#### 3.2.1 业务管理

- 创建业务（名称、描述）
- 编辑业务信息
- 删除业务（级联删除环境、Case、文件）
- 业务列表展示

#### 3.2.2 环境管理

- 创建环境（URL、浏览器配置、登录配置、忽略规则）
- 支持三种认证方式：
  - `none`：无需登录
  - `sso`：SSO 用户名密码登录
  - `cookies`：直接注入 Cookies
- 编辑/删除环境

#### 3.2.3 Case 管理

- 创建/编辑 Case（名称、描述、是否需要登录、步骤列表）
- YAML 批量导入
- YAML 导出
- 删除 Case

#### 3.2.3.1 单用例编辑页（全屏页面）

**路由设计**：

- 编辑已有用例：`/business/:businessId/case/:caseId`
- 创建新用例：`/business/:businessId/case/new`
- 从用例列表点击「编辑」或「新建」时，通过路由导航进入全屏编辑页（替代原有弹窗）

**页面布局（两栏 + Tab 切换）**：

- **左侧 - 用例编辑区**（Tab 切换）：
  - 📋 **表单编辑**：用例名称、登录配置、快照配置、测试步骤（Action/Verify）、参数等
  - 📝 **YAML 编辑**：YAML 语法编辑器，与表单实时双向同步（切换 Tab 时自动同步最新内容）
- **右侧 - Debug 面板**：环境/模型选择、开始调试按钮、实时执行日志、浏览器监控（置灰）、查看报告
- 两栏布局，左右各占 50%，一屏内同时可见编辑内容和调试结果

**Debug 模式**：

- **触发方式**：用户在右侧面板选择环境和模型后，点击「开始调试」
- **执行方式**：调用现有 `POST /executions` API，传入 `trigger_type: "debug"`，只传单个 test case ID
- **实时日志**：复用 `GET /executions/:id/progress` API 轮询获取实时执行日志，在右侧面板中展示
- **浏览器监控**：视频监控功能先置灰，显示「功能开发中」提示
- **查看报告**：调试完成后，显示「查看测试报告」按钮，跳转 OSS 报告链接
- **不保存历史**：Debug 执行记录不在「执行历史」页面中展示（通过 `trigger_type: "debug"` 过滤）

**Debug 执行流程**：

```
用户编辑 YAML → 保存用例 → 选择环境 + 模型 → 点击「开始调试」
                                                     ↓
                                         调用 createExecution API
                                         (trigger_type: "debug", 单个 case)
                                                     ↓
                                         轮询 getExecutionProgress API
                                         实时展示执行日志
                                                     ↓
                                         执行完成 → 展示「查看报告」按钮
```

#### 3.2.4 手动执行

- 选择业务 + 环境 + Cases
- 选择模型和并发数
- 触发执行，返回执行 ID
- 执行完成后查看报告

#### 3.2.5 执行记录

- 全局执行历史列表
- 按业务/环境/状态筛选
- 查看执行详情和报告

#### 3.2.6 定时任务

**核心功能**：

- 创建定时任务（名称、描述、Cron 表达式）
- 选择执行环境（单环境配置）
- 选择测试用例（多选）
- 选择 LLM 模型和并发数
- 启用/禁用任务
- 编辑/删除任务

**执行策略**：

- 每个业务可创建多个定时任务
- 一个定时任务配置一个环境 + 多个测试用例
- 执行时读取最新的 Case 内容（不保存快照）
- 定时触发和手动触发可以并行执行
- 同一业务下多个定时任务可以并行执行
- 系统全局最多 5 个并发任务，超过则自动排队

**并发控制**：

- 系统全局 `MAX_CONCURRENT_JOBS=5`
- 超过并发上限时任务自动排队
- 排队任务每 5 秒检查一次空闲槽位
- 同一定时任务不会重复执行（`max_instances=1`）

**Cron 表达式**：

- 标准 5 字段格式：`分 时 日 月 周`
- 前后端都需要验证 Cron 表达式
- 前端显示下一次执行时间（UTC+8 时区）
- 推荐使用 Cron 可视化编辑器

**执行记录**：

- 通过 `trigger_type` 字段区分手动/定时触发
- 通过 `scheduled_task_id` 关联定时任务
- 不需要单独展示，统一在执行记录列表中
- 执行失败不自动重试

#### 3.2.7 文件管理

- 上传业务文件到 OSS
- 文件列表展示
- Case step 中可引用文件
- 删除文件

## 4. 执行状态设计

### 4.1 状态分层

执行状态分为两个层面：

**1. 执行层面状态 (status 字段)**

| status      | 说明                                      |
| ----------- | ----------------------------------------- |
| `pending`   | 等待执行                                  |
| `running`   | 执行中                                    |
| `completed` | ✅ 执行完成（Agent 正常结束，可查看报告） |
| `failed`    | ❌ 执行失败（调度错误、Agent 崩溃等异常） |
| `timeout`   | ⏰ 执行超时（超过 JOB_TIMEOUT_SECONDS）   |

**2. Case 结果统计 (result_count 字段)**

```json
{
  "total": 10,
  "passed": 8,
  "failed": 1,
  "warning": 1
}
```

### 4.2 前端展示逻辑

- `status=completed` 时：展示 Case 结果统计和报告链接
- `status=failed` 时：展示错误信息
- `status=timeout` 时：展示超时提示
- `status=running` 时：展示进度/加载状态

## 5. 用例流程

### 5.1 手动执行流程

```
用户 → 选择业务 → 选择环境 → 选择 Cases → 选择模型 → 触发执行
                                                        ↓
                                              创建 Execution 记录
                                                        ↓
                                              启动 Agent 执行 + 日志输出
                                                        ↓
                                              Agent 回调通知完成
                                                        ↓
                                              上传报告到 OSS
                                                        ↓
                                              用户查看报告
```

### 5.2 定时执行流程

```
定时触发 → 读取任务配置 → 遍历多环境配置
                              ↓
                    读取最新 Case 内容
                              ↓
                    创建 Execution 记录
                              ↓
                    启动 Agent 执行 + 日志输出
                              ↓
                    Agent 回调通知完成
                              ↓
                    上传报告到 OSS
```
