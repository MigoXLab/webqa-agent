# 测试用例管理平台 - 需求设计文档

## 1. 项目背景

本项目旨在构建一个业务测试用例管理和执行平台，支持：

- 业务环境(URL)和测试用例(Case)的增删改查
- 每个业务的 Case 通过 YAML 解析上传，也支持手动编写
- 每个业务的文件库管理（用于上传功能时选择文件）
- 用户执行
  - 可以通过选择业务环境和 Case 触发执行，返回测试报告 URL
  - 定时触发执行
- 执行结果记录管理（手动 + 定时）

## 2. 业务模型

```
业务
├── Case 池（30个统一管理）
│   ├── case1 [需登录] ✓
│   ├── case2 [需登录] ✓
│   ├── case3 [免登录] ✓
│   └── ...
│
├── 环境（URL + 登录配置 + ignore_rules）
│   ├── 生产 (https://chat.intern-ai.org.cn) + SSO登录 + 忽略规则
│   └── 测试 (https://staging.chat.intern-ai.org.cn) + SSO登录 + 忽略规则
│
├── 文件库（用于 Case step 选择）
│   ├── test.jpg
│   └── sample.pdf
│
└── 定时任务（支持多环境配置，读取最新 Case）
    ├── "生产" → [环境:生产 + 20个case（其中10个登录，10个免登录）]
    └── "测试" → [环境:测试 + 25个case（其中15个登录，10个免登录）]
```

```
执行结果展示
展示所有触发的执行结果：
报告 OSS URL、执行状态、执行时间、结果概览
```

## 3. 功能范围（MVP）

### 3.1 优先级划分

| 优先级 | 功能      | 说明                                             |
| ------ | --------- | ------------------------------------------------ |
| **P0** | 业务管理  | 业务的增删改查                                   |
| **P0** | 环境管理  | 环境（URL + 登录配置 + ignore_rules）的增删改查  |
| **P0** | Case 管理 | Case 的增删改查、YAML 导入/导出                  |
| **P0** | 手动执行  | 选择环境 + Cases 触发执行                        |
| **P0** | 执行记录  | 查看执行历史和报告（OSS）**【全局】**            |
| **P1** | 定时任务  | Cron 表达式定时执行，支持多环境配置 **【全局】** |
| **P1** | 文件管理  | 业务文件库上传，Case step 可选择                 |

### 3.2 功能详述

#### 3.2.1 业务管理

- 创建业务（名称、描述）
- 编辑业务信息
- 删除业务（级联删除环境、Case、文件）
- 业务列表展示

#### 3.2.2 环境管理

- 创建环境（URL、浏览器配置、登录配置、忽略规则）
- 支持三种认证方式：
  - `none`：无需登录
  - `sso`：SSO 用户名密码登录
  - `cookies`：直接注入 Cookies
- 编辑/删除环境

#### 3.2.3 Case 管理

- 创建/编辑 Case（名称、描述、是否需要登录、步骤列表）
- YAML 批量导入
- YAML 导出
- 删除 Case

#### 3.2.4 手动执行

- 选择业务 + 环境 + Cases
- 选择模型和并发数
- 触发执行，返回执行 ID
- 执行完成后查看报告

#### 3.2.5 执行记录

- 全局执行历史列表
- 按业务/环境/状态筛选
- 查看执行详情和报告

#### 3.2.6 定时任务

- 创建定时任务（Cron 表达式）
- 支持多环境配置（一个任务可配置多个环境+Case组合）
- 启用/禁用任务
- 执行时读取最新 Case 内容

#### 3.2.7 文件管理

- 上传业务文件到 OSS
- 文件列表展示
- Case step 中可引用文件
- 删除文件

## 4. 执行状态设计

### 4.1 状态分层

执行状态分为两个层面：

**1. 执行层面状态 (status 字段)**

| status      | 说明                                      |
| ----------- | ----------------------------------------- |
| `pending`   | 等待执行                                  |
| `running`   | 执行中                                    |
| `completed` | ✅ 执行完成（Agent 正常结束，可查看报告） |
| `failed`    | ❌ 执行失败（调度错误、Agent 崩溃等异常） |
| `timeout`   | ⏰ 执行超时（超过 JOB_TIMEOUT_SECONDS）   |

**2. Case 结果统计 (result_count 字段)**

```json
{
  "total": 10,
  "passed": 8,
  "failed": 1,
  "warning": 1
}
```

### 4.2 前端展示逻辑

- `status=completed` 时：展示 Case 结果统计和报告链接
- `status=failed` 时：展示错误信息
- `status=timeout` 时：展示超时提示
- `status=running` 时：展示进度/加载状态

## 5. 用例流程

### 5.1 手动执行流程

```
用户 → 选择业务 → 选择环境 → 选择 Cases → 选择模型 → 触发执行
                                                        ↓
                                              创建 Execution 记录
                                                        ↓
                                              启动 Agent 执行 + 日志输出
                                                        ↓
                                              Agent 回调通知完成
                                                        ↓
                                              上传报告到 OSS
                                                        ↓
                                              用户查看报告
```

### 5.2 定时执行流程

```
定时触发 → 读取任务配置 → 遍历多环境配置
                              ↓
                    读取最新 Case 内容
                              ↓
                    创建 Execution 记录
                              ↓
                    启动 Agent 执行 + 日志输出
                              ↓
                    Agent 回调通知完成
                              ↓
                    上传报告到 OSS
```
