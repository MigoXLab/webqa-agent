## 1. 产品设计概述

### 1.1 核心理念

**AI 自动探索测试 (Gen Mode)** 旨在改变传统的 Web 自动化测试范式，从“手动编写/录制脚本”转向“声明式意图测试”。用户只需提供目标 URL 和自然语言形式的业务测试目标，AI Agent 即可自主分析页面结构、规划测试用例并完成全流程的执行与验证。

### 1.2 目标用户与使用场景

- **目标用户**：QA、vibecoding人群、外包QA
- **使用场景**：
  - **快速迭代与回归**：版本更新后，快速拉起 AI 代理检查核心链路（如登录、加购、结算），无需维护脆弱的固定脚本。
  - **探索性测试**：利用 AI 的遍历和识别能力，发掘页面中的死链、性能瓶颈和异常交互。
  - **零脚本起步**：为新业务系统快速建立自动化测试基线。

### 1.3 核心功能拆解

- **多维度测试支持**：
  - **功能测试 (Functional)**：基于自然语言目标的探索测试。
  - **性能分析 (Lighthouse)**：页面性能、可访问性及 SEO 评分。
  - **遍历测试 (Traverse Clickable Elements)**：自动化点击页面可交互元素，探测异常报错。
  - **链接检查 (Detect Dynamic Links)**：深度发现和校验页面内所有动态跳转链接。
- **阶段性演进策略**：
  - **一期（当前实现）**：直通式体验。配置 -> AI 全流程（规划+执行） -> 产出最终测试报告。最大化复用现有的执行详情与报告基建。
  - **二期（未来规划）**：交互式用例树。AI 生成用例树 -> 用户审查/微调 -> 保存为固定测试用例（沉淀到 Case 池）或继续执行。

## 2. 交互流程设计 (User Journey)

### 2.1 一期流程（直通式全流程）

1. **入口**：用户在系统主导航或业务详情页，点击「AI 自动探索测试」按钮。
2. **配置意图**：
   进入独立配置页，输入目标 URL，选择测试项目（功能、性能、遍历等）。支持输入一段自然语言描述的“测试目标”。
   agent的动态反思、replan都默认关闭，可手动开启【需修改agent实现】
3. **启动生成**：点击「开始探索」，系统后台分配执行环境与资源（K8s Job / 子进程），创建独立的 Execution 记录。
4. **实时监控【需修改agent实现】**：页面自动跳转至执行详情页。用户可实时查看到 Agent 规划的测试步骤、页面截图以及执行日志。
5. **获取报告**：测试结束后，生成包含具体步骤与断言结果的 HTML 报告和结构化结果。

## 3. UI 界面设计细节

UI 风格需贴近现有系统的现代化、简洁化（遵循 `FRONTEND_STYLE_GUIDE.md`），并强调“AI 智能”的体感。

### 3.1 探索测试配置页 (`GenPage.tsx`)

**页面布局**：居中的卡片式设计（Max-width 容器），提供专注的表单填写体验。

**核心 UI 元素**：

- **Header 区域**：
  - 图标：使用 `Sparkles` (紫色的闪粉图标) 强调 AI 属性。
  - 标题：「AI 自动探索测试」。
  - 副标题：「AI 将根据你的目标自动规划并执行全流程测试」。
- **表单区域**：
  - **目标 URL**：必填文本框，支持完整的 URL 格式校验。
  - **测试项目 (Test Items)**：采用多选 Button Group（药丸/标签样式），选中状态呈现明显的品牌色（如 `bg-purple-50`、`border-purple-300`）。
  - **测试目标 (Business Objectives)**：
    - **交互**：多行文本域（Textarea），提供清晰的 Placeholder（例如：“测试用户登录、搜索、购物车等核心功能是否正常”），引导用户进行优质的 Prompt 输入。
  - **模型选择 (Model)**：下拉框，默认自动拉取后端可用模型。
  - **高级选项 (Advanced Options)**：
    - 多维度测试：功能、性能、遍历
    - 并发数（Workers）配置，允许用户调节agent执行反思。
- **操作栏**：
  - 提交按钮：「开始探索」。
  - 状态反馈：点击后进入 `loading` 状态（显示 `Loader2` 旋转动画），按钮禁用防连抖。下方如有校验错误则展示红色背景的错误提示框。

### 3.2 探索测试详情页 (复用 `ExecutionPage`)

**复用现有执行基建，增加对 AI 决策过程的展示。**

- **进度概览**：展示当前处于“规划中”、“执行中”或“生成报告”阶段。
- **流式日志展示**：展示 Agent 的思考过程（Thought Process），这对于增加 AI 的可解释性与用户的信任感至关重要。
- **实时监控【需修改agent实现，要讨论】**：可实时查看到 Agent 规划的测试步骤、页面截图以及执行日志。
- **多媒体回放**：展示实时截图。

### 2.2 二期流程（交互式用例树）【需修改agent实现】

二期设计的核心是转变为“AI 探索规划 + 人类审查微调 + 只能执行”。

#### 1. 交互流程设计

1. **入口与配置**：与一期相同，用户填写 URL 与测试目标。
2. **增量规划展示**：点击开始后，页面进入「规划中」状态。左侧的 CaseTree 会随着 AI 的思考**实时生长**（例如先出现“用户模块”，再出现“登录”、“注册”等子节点）。
3. **审查与微调 (Review)**：
   - 规划完成后，Agent 暂停并等待。
   - 用户在左侧树中勾选或取消勾选需要执行的用例。
   - 点击具体用例，在右侧的 DetailPanel 预览具体步骤，并可进行手动修改（如修改某个预期断言）。
4. **决策分流**：
   - **「保存到 Case 池」**：仅将这批满意的用例保存为系统沉淀的自动化资产，不再立即执行。
   - **「保存并执行」**：保存用例，并立刻下发至 K8s/子进程进行实质性的操作运行。

- **ConfigBar (顶部配置栏)**：浓缩一期的表单选项（URL、环境、目标），支持调整参数后快速点击“重新生成”。
- **CaseTree (左侧树状视图 55%)**：
  - **动态生长动画**：随着 AI 解析出新的业务模块与用例，树节点从左侧滑入（如“结算模块”显示“正在生成”状态）。
  - **状态与勾选**：每个分组和用例节点带勾选框，支持单选/全选，方便用户按需挑选。
- **DetailPanel (右侧详情面板 45%)**：
  - 选中某个节点后，右侧展示详细的基础信息和测试步骤（只读列表视图/YAML视图）。
  - **编辑能力**：允许用户人工修正 AI 生成的不合理断言或点击步骤（复用现有的 CaseEditor）。
- **ActionBar (底部/右下操作栏)**：
  - 展示当前已选中的用例数量。
  - 「保存到用例池」：将勾选的用例作为自动化资产持久化，标记来源为 `gen`。
  - 「保存并执行」：保存用例并立刻下发派行（退化为 Run 模式）。
